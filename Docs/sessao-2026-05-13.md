## 1. Resumo da Sessão

Sessão focada em três frentes:

**Frente 1 — Pipeline de Compradores (`/pipeline`):**  
Adicionada funcionalidade "Editar Sugestões" dentro do modal "Buscar Imóveis", permitindo ao corretor adicionar ou remover manualmente imóveis da lista de compatíveis de um lead.

Atualização dos cards de resumo e das abas de status para refletir o fluxo real de um contrato jurídico (Rascunhos → Aguardando Revisão → Ajustes Solicitados → Aprovados → Assinados).

**Frente 3 — Novo Contrato — Wizard multi-step (`/contracts/novo`):**  
Implementação completa das 8 etapas do formulário de criação de contrato, do zero. Este foi o maior trabalho da sessão — duas sessões de contexto foram necessárias para concluir (a sessão anterior implementou Steps 1–6 + Step 7 parcialmente; esta sessão finalizou o Step 7 e implementou o Step 8 completo).

#### Step 2 — Vendedores/Cedentes

**Estrutura:** lista de vendedores com Add/Remove. Mínimo 1, sempre. Cada vendedor tem:

**Seção Principal:**

- Nome completo, CPF, RG, Data de Nascimento, Gênero, Estado Civil
- Endereço completo (Logradouro, Número, Complemento, Bairro, Cidade, Estado/UF — Select com 27 estados)
- E-mail, Telefone, Profissão, Nacionalidade

**Certidões Automáticas** (collapsible, pré-expandido):

- Cada certidão tem: nome + órgão + badge de status + botão "Buscar" / "Pendente" + data de validade quando disponível

**Certidões Manuais** (collapsible):
- Área de upload de arquivos com botão "Adicionar Certidão Manual" e campo Nome + arquivo

**Dados Bancários:**
- Banco (Input texto), Chave PIX, Agência, Conta

**Interface:** `VendedorData { _id, isPJ, nome, cpf, rg, dataNasc, genero, estadoCivil, logradouro, numero, complemento, bairro, cidade, estado, email, telefone, profissao, nacionalidade, cnpj, razaoSocial, banco, chavePix, agencia, conta, certAutoOpen, certManualOpen }`

## 6. Convenções Consolidadas do Projeto

### Padrão de dados mockados
Arrays exportados de módulo (`export const items: Item[] = [...]`). Mutação direta via splice/push.  
Ao migrar para banco: substituir por Server Actions com Drizzle.

### CSS
- **Zero valores hardcoded** — tudo via tokens (`var(--size-*)`, `var(--font-size-*)`, `var(--color-*)`)
- Um `.module.css` por componente/página, ao lado do `.tsx`
- BEM dentro dos módulos: `.card`, `.card__header`, `.card--active`
- Utilitário de classe: `cn()` de `@/lib/utils` (wrapper de `clsx`)

### Componentes globais — nunca recriar
`Button`, `Card / CardHeader / CardBody`, `Input / Select`, `StatCard`, `Modal`, `Topbar`, `Sidebar`

### Componentes locais do wizard (`/contracts/novo/page.tsx`)
`CurrencyInput`, `PctInput`, `DayInput`, `ProgressBar` — são componentes puramente locais e não devem ser importados de fora da página. Se necessário em outros contextos, mover para `components/ui/`.

### Padrão de Select
O componente `Select` de `@/components/ui/Input` é um `<select>` nativo estilizado. Usar com children `<option>`:
```tsx
<Select label="Tipo" value={val} onChange={e => onChange({ tipo: e.target.value })}>
  {OPCOES.map(o => <option key={o} value={o}>{o}</option>)}
</Select>
```

### CustomSelect vs Select
O `CustomSelect` em `/analise-mercado/nova/` usa React Portal para evitar clipping por `overflow: hidden`. Usar dentro de qualquer componente com `overflow: hidden` (ex: `Card`). Para formulários em pages sem Cards, o `Select` nativo é suficiente.
