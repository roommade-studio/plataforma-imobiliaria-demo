#### 3.1.6 Função `buildGroups` — agrupamento do histórico

```typescript
function buildGroups(camps: Campaign[]): { key: string; campaigns: Campaign[] }[] {
  const groups = []
  const seen   = new Set<string>()
  for (const camp of camps) {
    const key = camp.requestId ?? camp.id
    if (!seen.has(key)) {
      seen.add(key)
      groups.push({
        key,
        campaigns: camp.requestId
          ? camps.filter(c => c.requestId === camp.requestId)
          : [camp],
      })
    }
  }
  return groups
}
```

Preserva a ordem de chegada dos grupos. Um grupo com `requestId` agrupa todos os itens com aquele ID.

### 3.2 Bug fix — StatCard `variant="accent"` — fundo azul escuro

**Arquivo modificado:**
- `components/ui/StatCard.module.css`

**Causa raiz:**

A classe `.card--accent` usava `var(--btn-primary-background)` (= `var(--brand-600)` = `#2452e0` no tema claro) como cor de fundo, e `var(--btn-primary-text)` (branco) para todos os textos. Isso literalmente colava as cores de um botão primário sobre uma superfície de card, resultando em um fundo azul marinho opaco completamente fora do padrão visual da plataforma.

**Correção:**

```css
/* Antes */
.card--accent {
  background-color: var(--btn-primary-background);
  border-color: var(--btn-primary-border);
}
.card--accent .card__label,
.card--accent .card__value,
.card--accent .card__suffix {
  color: var(--btn-primary-text);
}

/* Depois */
.card--accent {
  background-color: var(--brand-50);    /* #f0f4ff — tinte azul levíssimo */
  border-color:     var(--brand-200);   /* #c2d4fe — borda azul sutil */
}
.card--accent .card__label  { color: var(--paragraph); }
.card--accent .card__value  { color: var(--heading-accent); }  /* brand-600 */
.card--accent .card__suffix { color: var(--heading-accent); }
.card--accent .card__icon   { color: var(--heading-accent); }
```

O padrão `brand-50` de fundo + `brand-200` de borda + `heading-accent` no valor é o mesmo padrão de superfícies de acento usado em banners informacionais (`--info-50` / `--info-200`) e badges, tornando o card consistente com o restante do design system.

**Abrangência do fix:**

O bug afetava todos os StatCards com `variant="accent"` em toda a plataforma — 14 ocorrências identificadas em páginas distintas:

`/metrics`, `/dashboard`, `/pipeline`, `/seller-pipeline`, `/properties-kanban`, `/market-study`, `/analise-mercado`, `/mentoria`, `/benchmarking`, `/gestor-trafego`, `/fundo-marketing`, `/gestor/fundo-marketing`, `/fluxo-caixa`, `/admin/financeiro/fluxo-caixa`

Todos corrigidos com a mudança de um único arquivo de CSS.
