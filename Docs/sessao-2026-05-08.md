Preço Competitivo = Improvável × 0,85   (−15%)

## 5. Convenções do Projeto

### Padrão de dados mockados
Todos os dados vivem em **arrays exportados de módulos** (`export const items: Item[] = [...]`).  
As funções de mutação (`add`, `update`, `delete`) operam diretamente no array via splice/push.  
A persistência funciona apenas dentro da mesma sessão de servidor — ao reiniciar, volta ao estado inicial.  
Ao migrar para banco: substituir as funções de módulo por Server Actions ou Route Handlers com Drizzle.

### CSS
- **Zero valores hardcoded** — tudo via tokens (`var(--size-*)`, `var(--font-size-*)`, `var(--color-*)`)
- Um arquivo `.module.css` por componente/página, sempre ao lado do `.tsx`
- Nomenclatura BEM dentro dos módulos: `.card`, `.card__header`, `.card--active`
- Classe utilitária: `cn()` de `@/lib/utils` (wrapper de `clsx`)

### Componentes de UI globais
Nunca recriar alternativas. Sempre usar: `Button`, `Card`, `Input/Select/Textarea`, `StatCard`, `Modal`, `Topbar`, `Sidebar`.

### Importante: `CustomSelect` vs `Select`
O componente `Select` de `@/components/ui/Input` é um `<select>` nativo estilizado — adequado para formulários simples fora de Cards. O `CustomSelect` em `app/(dashboard)/analise-mercado/nova/` usa React Portal e deve ser usado **dentro de qualquer componente que tenha `overflow: hidden`**, como o `Card`. Se outros formulários dentro de Cards precisarem de dropdowns customizados, mover o `CustomSelect` para `components/ui/` ou criar uma cópia.
